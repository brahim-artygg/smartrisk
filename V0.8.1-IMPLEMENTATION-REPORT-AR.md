# SmartRisk Engine v0.8.1 — تقرير التنفيذ

## الهدف
إغلاق فجوات WebSocket، distributed workers، sandboxing، multi-provider failover، fuzzing/symbolic execution، وFP/FN calibration فوق v0.7/v0.8 مع إبقاء `unknown` وقيود الأدلة صريحة.

## ما تم إغلاقه

### WebSocket
- `eth_subscribe/newHeads` reconnectable subscriber.
- failover بين WebSocket providers.
- كل head يطلق RPC backfill/reconciliation عبر `ReorgAwareRealtimeIndexer`.
- WebSocket ليس canonical source؛ الـRPC/canonical layer هي مصدر الحقيقة.

### Distributed workers
- Redis Streams consumer groups.
- `XREADGROUP` للعمل الطبيعي و`XAUTOCLAIM` للاسترداد.
- durable job state، attempts، retry/final failure.
- reclaim window افتراضي 15 دقيقة مع CLI override.
- idempotent `run_id` ثابت لكل job.

### Sandboxing
- process isolation للـscan الكامل.
- POSIX resource limits للـCPU/RAM/file-size/open-files/processes.
- bubblewrap عند توفره مع network isolation افتراضي للـstatic tools.
- project workspace mapping صحيح داخل `/work`، مع writable submounts معلنة.
- host network لا يُفعل إلا opt-in في adapter المناسب.

### Multi-provider failover
- health tracking.
- retries.
- circuit breaker.
- capability-aware suppression لطرق غير مدعومة.
- provider-aware raw evidence.
- environment-based routing لـEthereum وBNB.

### Fuzzing / symbolic
- deterministic calldata mutations.
- fork execution + trace coverage keys.
- bounded bytecode symbolic branch guidance.
- optional Z3 solving لقيود selector البسيطة.
- optional `FoundryDeepRunner` لتشغيل Foundry fuzz أو Halmos symbolic suites الموجودة مسبقًا تحت sandbox.

### Calibration
- train/holdout.
- group-aware split عند توفر `group_id` لتقليل leakage.
- duplicate `sample_id` rejection.
- threshold selection.
- Wilson intervals.
- Brier score + ECE.
- Platt-style calibration.

## حدود يجب عدم إخفائها
1. لا يوجد إثبات أن المعايرة النهائية تمثل الإنتاج حتى تتم إضافة corpus حقيقي مستقل وموسوم.
2. الـbuilt-in symbolic analyzer ليس complete EVM path proof.
3. Halmos/Foundry يحتاجان executables وtest harness؛ SmartRisk لا يعدل أو يولد harness تلقائيًا.
4. network isolation عبر bubblewrap تعتمد على دعم host؛ غيابها يظهر كتقليص capability بدل اعتباره نجاحًا.
5. لم يتم broadcast لأي transaction حقيقي أثناء الاختبارات.
