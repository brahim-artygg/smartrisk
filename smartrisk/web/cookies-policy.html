Cookies Policy

How SmartRisk uses cookies.

Why SmartRisk uses a cookie

When you sign in, SmartRisk uses a server-side session cookie named smartrisk_session so the application can recognize your authenticated session between requests.

How the session cookie is protected

The session cookie is issued as an HttpOnly cookie with SameSite=Lax. When SmartRisk is running over HTTPS, the cookie is also marked Secure.

What is stored in browser JavaScript storage

The SmartRisk web frontend does not use localStorage or sessionStorage for the authenticated session. The session token is kept in the protected browser cookie rather than page JavaScript storage.

Anonymous scanning

You can use the public scanner without creating an account. A sign-in session is only needed for account features such as authenticated Developer API access.

Logging out

Signing out clears the active SmartRisk session cookie. Deleting or blocking cookies in your browser can also prevent account features from working correctly.

Changes

SmartRisk may update this policy when the site's authentication or browser storage behavior changes. The wording on this page will be updated to match the service.
